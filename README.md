# Портфолио по аналитике данных

**Python · SQL · pandas · SQLite · Jupyter Notebook · Plotly**

В этом репозитории собраны три учебных проекта на основе технических заданий Яндекса. В каждом кейсе я разбирала исходную задачу, исследовала данные или существующий код, реализовывала решение и проверяла результат.

Основной акцент — не только на готовом коде, но и на **ходе анализа**: гипотезах, проверках, найденных ошибках и выводах. Подробный разбор каждого проекта находится в Jupyter Notebook.

## Проекты

| Проект | Что сделано | Инструменты |
|---|---|---|
| **[01. Пиковая нагрузка сервиса](01-peak-load/README.md)** | Нашла максимальную одновременную нагрузку и самое раннее время пика. Сравнила перебор с методом событий, добавила тесты и замеры скорости. | Python, pandas, matplotlib |
| **[02. Чиним дашборд](02-dashboard-debugging/README.md)** | Исследовала аномалии, исправила обработку пополнений, незавершённых когорт Retention и пустого фильтра подписок. Сравнила показатели до и после. | Python, pandas, SQLite, Dash, Plotly |
| **[03. Блэклист](03-blacklist-sql/README.md)** | Исправила три последовательных SQL-запроса, рассчитала пользовательские признаки по логам и заказам и проверила итоговую таблицу. | SQL, SQLite, Python, pandas |

## Результаты

**01. Пиковая нагрузка сервиса**

- Реализован алгоритм со сложностью `O(n log n)`.
- На примере из условия пик составил 109 единиц в момент 5.
- На локальном тесте с 200 000 запросов время выполнения составило около 0,107 с (одно измерение).

**02. Чиним дашборд**

- Восстановлено **1 250 541 ₽** пополнений за 2–4 августа 2026 года после исправления обработки `topup` / `top-up`.
- Для незавершённых когорт Retention исправлено отображение отсутствующих данных.
- Исправлено поведение фильтра подписок при пустом выборе.

**03. Блэклист**

- Сформирована итоговая таблица на 5 000 пользователей.
- Рассчитаны 8 пользовательских признаков.
- Проверены группировки по сессиям, расчёты заказов и диапазон конверсии.

## Как изучать проекты

В каждой папке находится отдельный `README.md` с описанием задачи, используемых инструментов и результатов.

Файлы `analysis.ipynb` содержат ход исследования: от первых наблюдений и гипотез до проверок и выводов.

Отдельные Python- и SQL-файлы содержат реализации решений.

## Подход к работе

В проектах я старалась придерживаться одной последовательности:

**Постановка задачи → изучение данных → гипотеза → проверка → решение → выводы.**

Для исправления дашборда использовала отдельные рабочие копии, не изменяя исходную базу данных.
